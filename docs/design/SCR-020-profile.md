**画面ID:** SCR-020  
**画面名:** プロフィール（My Profile）  
**Version:** 1.0.0  
**作成日:** 2026-02-16  

---

## 1. 画面概要

### 1.1 目的
ログイン中のユーザーが自身のプロフィール情報を確認・編集し、パスワードを変更する画面。

### 1.2 対象ユーザー
- 全ユーザー（admin / operator / viewer）

### 1.3 アクセス経路
- ヘッダーのユーザー名 / アバターをクリック
- URL 直接アクセス: `/profile`

### 1.4 表示形式
- フルページ画面（サイドバー内のコンテンツエリア）

## 3. 画面構成要素

### 3.1 プロフィール情報カード

| 要素 | タイプ | 説明 | 編集可否 |
|------|--------|------|----------|
| ユーザー名 | Text（読み取り専用） | ログインID | × |
| ロール | Badge（読み取り専用） | 現在のロール名 | × |
| 表示名 | Input | 画面に表示される名前 | ○ |
| メールアドレス | Input | メールアドレス | ○ |
| キャンセルボタン | Button (outline) | 変更を破棄 | - |
| 保存ボタン | Button (primary) | 変更を保存 | - |

### 3.2 パスワード変更カード

| 要素 | タイプ | 説明 |
|------|--------|------|
| 現在のパスワード | Input (password) | 現在のパスワードを入力 |
| 新しいパスワード | Input (password) | 新しいパスワードを入力 |
| 新しいパスワード（確認） | Input (password) | 確認用再入力 |
| パスワード変更ボタン | Button (primary) | パスワード変更を実行 |

## 4. 画面項目とイベント

### 4.1 初期表示時

#### イベント: ページロード
**処理内容:**
1. 現在のユーザープロフィール情報を取得
2. フォームに初期値を設定

**API呼び出し:**

```typescript
GET /api/v1/users/me

Response (200 OK):
{
  "success": true,
  "data": {
    "id": 1,
    "username": "admin",
    "display_name": "管理者 太郎",
    "email": "admin@example.com",
    "roles": [
      {
        "code": "admin",
        "name": "システム管理者"
      }
    ],
    "last_login_at": "2026-02-16T09:00:00Z",
    "created_at": "2026-02-01T00:00:00Z",
    "version": 1
  }
}
```

**エラーハンドリング:**
- 401: ログイン画面（SCR-010）へリダイレクト

---

### 4.2 プロフィール保存

#### イベント: 「保存」ボタンクリック
**処理内容:**
1. バリデーション実行
2. プロフィール更新 API 呼び出し
3. 成功: トースト表示 + フォームを更新後の値で再設定
4. 失敗: エラーメッセージ表示

**API呼び出し:**

```typescript
PUT /api/v1/users/me

Request:
{
  "display_name": "管理者 太郎",
  "email": "admin@example.com",
  "version": 1
}

Response (200 OK):
{
  "success": true,
  "data": {
    "id": 1,
    "username": "admin",
    "display_name": "管理者 太郎",
    "email": "admin@example.com",
    "roles": [
      {
        "code": "admin",
        "name": "システム管理者"
      }
    ],
    "version": 2
  }
}
```

**UI動作:**
- 成功: "プロフィールを更新しました" トースト表示
- 409 Conflict: "データが更新されています。再読み込みしてください" トースト + 再取得
- ヘッダーのユーザー名表示も更新

---

### 4.3 プロフィール編集キャンセル

#### イベント: 「キャンセル」ボタンクリック
**処理内容:**
1. フォームの値を初期表示時のデータに戻す

**API呼び出し:**
なし（クライアントサイド処理のみ）

---

### 4.4 パスワード変更

#### イベント: 「パスワードを変更」ボタンクリック
**処理内容:**
1. バリデーション実行
2. パスワード変更 API 呼び出し
3. 成功: トースト表示 + パスワードフォームクリア
4. 失敗: エラーメッセージ表示

**API呼び出し:**

```typescript
PUT /api/v1/users/me/password

Request:
{
  "current_password": "oldPassword123",
  "new_password": "newPassword456"
}

Response (200 OK):
{
  "success": true,
  "data": {
    "message": "パスワードを変更しました"
  }
}
```

**UI動作:**
- 成功: "パスワードを変更しました" トースト表示 + フォームクリア
- 401（現在のパスワード不一致）: "現在のパスワードが正しくありません" エラー表示
- パスワード変更後、既存の全セッション（他デバイス含む）を無効化するかは Phase 2 検討

**セキュリティ考慮:**
- パスワード変更成功時、Access Token を再発行（ADR-008: パスワード変更はブラックリスト登録トリガー）

## 5. バリデーション

### 5.1 表示名
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 空文字 | "表示名を入力してください" |
| 最大文字数 | 100文字超過 | "表示名は100文字以内で入力してください" |

### 5.2 メールアドレス
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 形式 | メール形式でない | "有効なメールアドレスを入力してください" |
| 最大文字数 | 255文字超過 | "メールアドレスは255文字以内で入力してください" |
| 重複チェック | 他ユーザーと重複 | "このメールアドレスは既に使用されています" |

### 5.3 現在のパスワード
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 空文字 | "現在のパスワードを入力してください" |

### 5.4 新しいパスワード
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 空文字 | "新しいパスワードを入力してください" |
| 最小文字数 | 8文字未満 | "パスワードは8文字以上で入力してください" |
| 現在と異なる | 現在のパスワードと同一 | "現在のパスワードと異なるパスワードを入力してください" |

### 5.5 新しいパスワード（確認）
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 空文字 | "確認用パスワードを入力してください" |
| 一致 | 新しいパスワードと不一致 | "パスワードが一致しません" |

## 6. エラーハンドリング

| エラー種別 | HTTP Status | UI動作 |
|-----------|-------------|--------|
| 認証切れ | 401 | ログイン画面へリダイレクト |
| バリデーションエラー | 400 | フィールド下にエラーメッセージ表示 |
| パスワード不一致 | 401 | "現在のパスワードが正しくありません" |
| メール重複 | 409 | "このメールアドレスは既に使用されています" |
| 楽観ロック競合 | 409 | トースト + 再読み込み |
| サーバーエラー | 500 | "システムエラーが発生しました" トースト |

## 7. 非機能要件

### 7.1 パフォーマンス
- 初期表示: 1秒以内
- プロフィール保存: 500ms 以内
- パスワード変更: 1秒以内（bcrypt ハッシュ計算あり）

### 7.2 アクセシビリティ
- フォームフィールドはキーボード操作可能
- aria-label の適切な設定
- 読み取り専用フィールドは aria-readonly="true" を設定

### 7.3 レスポンシブ対応
- モバイル: カード幅 100%（1カラム）
- デスクトップ: カード幅 最大 600px（中央配置）

## 8. 実装メモ

### 8.1 使用コンポーネント（shadcn/ui）
- Card: プロフィールカード / パスワード変更カード
- Input: テキスト・パスワード入力
- Button: 保存・キャンセル・パスワード変更
- Badge: ロール表示
- Label: フォームラベル
- Toast: 成功/エラー通知
- Separator: セクション区切り

### 8.2 状態管理
```typescript
interface ProfileState {
  profile: {
    id: number;
    username: string;
    display_name: string;
    email: string;
    roles: { code: string; name: string }[];
    version: number;
  } | null;
  isLoading: boolean;
  isSaving: boolean;
  error: string | null;
}

interface PasswordChangeState {
  currentPassword: string;
  newPassword: string;
  confirmPassword: string;
  isChanging: boolean;
  error: string | null;
}
```
