**画面ID:** SCR-030  
**画面名:** ユーザー管理（User Management）  
**Version:** 1.0.0  
**作成日:** 2026-02-16  

---

## 1. 画面概要

### 1.1 目的
システム管理者（admin）がユーザーアカウントを管理する画面。ユーザーの一覧表示、新規作成、編集、有効/無効切替、パスワードリセットを行う。

### 1.2 対象ユーザー
- **admin ロールのみ**（operator / viewer はアクセス不可）

### 1.3 アクセス経路
- サイドバーメニュー「ユーザー管理」をクリック（admin ロールの場合のみ表示）
- URL 直接アクセス: `/users`（権限チェックあり）

### 1.4 必要パーミッション
- `user:read` — 一覧・詳細表示
- `user:create` — 新規作成
- `user:update` — 編集・ロール変更
- `user:delete` — 有効/無効切替

## 3. 画面構成要素

### 3.1 ヘッダーアクション

| 要素 | 説明 |
|------|------|
| ページタイトル | "👥 ユーザー管理" |
| 新規ユーザー作成ボタン | ユーザー作成ダイアログを開く |

### 3.2 検索・フィルタバー

| 要素 | タイプ | 説明 |
|------|--------|------|
| キーワード検索 | Input | 表示名 / メールアドレスで部分一致検索 |

### 3.3 ユーザー一覧テーブル

| 列名 | 幅 | ソート | 説明 |
|------|-----|--------|------|

| メールアドレス | 200px | ○ | メールアドレス |

| ロール | 色 | 表示名 |
|--------|-----|--------|
| admin | パープル系 | システム管理者 |
| operator | ブルー系 | オペレーター |

| ステータス | 色 | 表示名 |
|-----------|-----|--------|
| Active | グリーン系 | 有効 |

## 4. 画面項目とイベント

### 4.1 初期表示時

#### イベント: ページロード
**処理内容:**
1. 権限チェック（admin ロールであることを確認）
2. ユーザー一覧データを取得
3. テーブルに表示

**権限チェック:**
- admin ロール以外がアクセスした場合: Dashboard（SCR-001）へリダイレクト
- アクセス拒否トースト: "このページにアクセスする権限がありません"

**API呼び出し:**

```typescript
GET /api/v1/users?page=1&size=20

Response (200 OK):
{
  "success": true,
  "data": [
    {

      "email": "admin@example.com",
      "is_active": true,
      "roles": [
        {
          "code": "admin",
          "name": "システム管理者"
        }
      ],
      "last_login_at": "2026-02-16T09:00:00Z",
      "created_at": "2026-02-01T00:00:00Z",
      "version": 1
    }
  ],
  "total": 4,
  "page": 1,
  "size": 20
}
```

---

### 4.2 キーワード検索

#### イベント: 検索入力 + Enter
**処理内容:**
1. 入力値を取得
2. API呼び出し

**API呼び出し:**

```typescript
GET /api/v1/users?keyword=太郎&page=1&size=20
```

**検索対象:**
- `display_name`: 表示名（部分一致、大文字小文字区別なし）
- `email`: メールアドレス（部分一致、大文字小文字区別なし）

---

### 4.3 フィルタ変更

#### イベント: Select 変更
**処理内容:**
1. 選択値を取得
2. API呼び出し

**API呼び出し:**

```typescript
GET /api/v1/users?role=operator&is_active=true&page=1&size=20
```

### 4.4 新規ユーザー作成

#### イベント: 「新規ユーザー作成」ボタンクリック → ダイアログ表示 → 「作成」ボタンクリック

**フォーム項目:**

| 項目 | 必須 | 説明 |
|------|------|------|
| ユーザー名 | ○ | ログインID（一意）|
| 表示名 | ○ | 画面表示用の名前 |
| メールアドレス | × | メールアドレス |
| ロール | ○ | admin / operator / viewer |
| 初期パスワード | ○ | 初期パスワード |

**API呼び出し:**

```typescript
POST /api/v1/users

Request:
{
  "username": "tanaka",
  "display_name": "田中 三郎",
  "email": "tanaka@example.com",
  "role": "viewer",
  "password": "initialPassword123"
}

Response (201 Created):
{
  "success": true,
  "data": {
    "id": 5,
    "username": "tanaka",
    "display_name": "田中 三郎",
    "email": "tanaka@example.com",
    "is_active": true,
    "roles": [
      {
        "code": "viewer",
        "name": "閲覧者"
      }
    ],
    "created_at": "2026-02-16T11:00:00Z",
    "version": 1
  }
}
```

**UI動作:**
- 成功: "ユーザーを作成しました" トースト + ダイアログを閉じる + 一覧更新
- ユーザー名重複: "このユーザー名は既に使用されています" エラー

---

### 4.5 ユーザー編集

#### イベント: 編集アイコン（✏️）クリック → ダイアログ表示 → 「保存」ボタンクリック

**フォーム項目（編集時）:**

| 項目 | 必須 | 編集可否 | 説明 |
|------|------|----------|------|
| ユーザー名 | ○ | × | 変更不可（読み取り専用で表示）|
| 表示名 | ○ | ○ | 画面表示用の名前 |
| メールアドレス | × | ○ | メールアドレス |
| ロール | ○ | ○ | admin / operator / viewer |

**API呼び出し:**

```typescript
PUT /api/v1/users/:id

Request:
{
  "display_name": "田中 三郎（更新）",
  "email": "tanaka-new@example.com",
  "role": "operator",
  "version": 1
}

Response (200 OK):
{
  "success": true,
  "data": {
    "id": 5,
    "username": "tanaka",
    "display_name": "田中 三郎（更新）",
    "email": "tanaka-new@example.com",
    "is_active": true,
    "roles": [
      {
        "code": "operator",
        "name": "オペレーター"
      }
    ],
    "version": 2
  }
}
```

**UI動作:**
- 成功: "ユーザー情報を更新しました" トースト + ダイアログを閉じる + 一覧更新
- 409 Conflict: "データが更新されています。再読み込みしてください"

**制約:**
- 自分自身のロールは変更不可（admin が自分の admin ロールを削除できない）
- service ロールのユーザーは編集対象外（一覧にも表示しない）

---

### 4.6 ユーザー有効/無効切替

#### イベント: ステータスバッジクリック or コンテキストメニュー → 確認ダイアログ → 「実行」

**処理内容:**
1. 確認ダイアログ表示
   - 有効化: "このユーザーを有効にしますか？"
   - 無効化: "このユーザーを無効にしますか？ 無効化すると、このユーザーはログインできなくなります。"
2. API呼び出し
3. 成功: 一覧更新

**API呼び出し:**

```typescript
PUT /api/v1/users/:id/status

Request:
{
  "is_active": false,
  "version": 1
}

Response (200 OK):
{
  "success": true,
  "data": {
    "id": 5,
    "is_active": false,
    "version": 2
  }
}
```

**UI動作:**
- 無効化成功: "ユーザーを無効化しました" トースト + 該当行のバッジ更新
- 有効化成功: "ユーザーを有効化しました" トースト + 該当行のバッジ更新

**制約:**
- 自分自身は無効化不可（ボタンを非活性化）
- 無効化時、対象ユーザーの全トークンをブラックリストに追加（即時ログアウト）

---

### 4.7 パスワードリセット

#### イベント: 🔑 アイコンクリック → 確認ダイアログ → 「リセット」

**処理内容:**
1. パスワードリセットダイアログ表示
2. 新しいパスワードを入力
3. API呼び出し
4. 成功: トースト表示

**ダイアログ内容:**

```
┌────────────────────────────────────┐
│ [×] パスワードリセット             │
├────────────────────────────────────┤
│                                    │
│ ユーザー: tanaka (田中 三郎)       │
│                                    │
│ 新しいパスワード *                 │
│ [________________________]        │
│                                    │
│ ⚠️ リセット後、このユーザーの      │
│ 全セッションが無効化されます。     │
│                                    │
│  [キャンセル]  [リセット]          │
│                                    │
└────────────────────────────────────┘
```

**API呼び出し:**

```typescript
PUT /api/v1/users/:id/password

Request:
{
  "new_password": "newPassword123"
}

Response (200 OK):
{
  "success": true,
  "data": {
    "message": "パスワードをリセットしました"
  }
}
```

**UI動作:**
- 成功: "パスワードをリセットしました。新しいパスワードをユーザーに通知してください。" トースト

**セキュリティ考慮:**
- パスワードリセット時、対象ユーザーの全 Access Token をブラックリストに追加
- 対象ユーザーの全 Refresh Token を Redis から削除（強制再ログイン）
- 監査ログに記録

## 5. バリデーション

### 5.1 ユーザー名（新規作成時のみ）
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 空文字 | "ユーザー名を入力してください" |
| 最小文字数 | 3文字未満 | "ユーザー名は3文字以上で入力してください" |
| 最大文字数 | 50文字超過 | "ユーザー名は50文字以内で入力してください" |
| 使用可能文字 | 英数字・ハイフン・アンダースコア以外 | "ユーザー名は英数字、ハイフン、アンダースコアのみ使用できます" |
| 重複チェック | 既存ユーザー名と重複 | "このユーザー名は既に使用されています" |

### 5.2 表示名
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 空文字 | "表示名を入力してください" |
| 最大文字数 | 100文字超過 | "表示名は100文字以内で入力してください" |

### 5.3 メールアドレス
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 形式 | メール形式でない | "有効なメールアドレスを入力してください" |
| 最大文字数 | 255文字超過 | "メールアドレスは255文字以内で入力してください" |

### 5.4 ロール
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 未選択 | "ロールを選択してください" |
| 有効値 | admin/operator/viewer 以外 | "有効なロールを選択してください" |

### 5.5 パスワード（新規作成 / リセット時）
| ルール | 条件 | エラーメッセージ |
|--------|------|-----------------|
| 必須 | 空文字 | "パスワードを入力してください" |
| 最小文字数 | 8文字未満 | "パスワードは8文字以上で入力してください" |

## 6. エラーハンドリング

| エラー種別 | HTTP Status | UI動作 |
|-----------|-------------|--------|
| 権限不足 | 403 | Dashboard へリダイレクト + トースト |
| バリデーションエラー | 400 | フィールド下にエラーメッセージ表示 |
| ユーザー名重複 | 409 | "このユーザー名は既に使用されています" |
| 楽観ロック競合 | 409 | トースト + 一覧再取得 |
| 自身の操作制限 | 400 | "自分自身のロール変更 / 無効化はできません" |
| サーバーエラー | 500 | "システムエラーが発生しました" トースト |

## 7. 非機能要件

### 7.1 パフォーマンス
- 初期表示: 1秒以内
- ユーザー作成/更新: 500ms 以内
- パスワードリセット: 1秒以内

### 7.2 アクセシビリティ
- テーブルはキーボード操作可能（Tab + Enter）
- ダイアログはフォーカストラップを実装
- aria-label の適切な設定

### 7.3 レスポンシブ対応
- モバイル: カード形式で表示
- デスクトップ: フルテーブル表示

## 8. 実装メモ

### 8.1 使用コンポーネント（shadcn/ui）
- Table: ユーザー一覧
- Dialog: ユーザー作成/編集/パスワードリセット
- Input: テキスト入力
- Select: ロール・ステータス選択
- Button: アクションボタン
- Badge: ロール・ステータス表示
- AlertDialog: 確認ダイアログ（無効化・パスワードリセット）
- Toast: 成功/エラー通知

### 8.2 状態管理
```typescript
interface UserManagementState {
  users: User[];
  total: number;
  page: number;
  size: number;
  filters: {
    keyword: string | null;
    role: string | null;
    is_active: boolean | null;
  };
  isLoading: boolean;
  error: string | null;
}

interface UserFormState {
  mode: 'create' | 'edit';
  isOpen: boolean;
  user: Partial<User> | null;
  isSaving: boolean;
  error: string | null;
}

interface User {
  id: number;
  username: string;
  display_name: string;
  email: string | null;
  is_active: boolean;
  roles: { code: string; name: string }[];
  last_login_at: string | null;
  created_at: string;
  version: number;
}
```

### 8.3 権限ガード
```typescript
// Route Guard: admin ロール以外は Dashboard へリダイレクト
function UserManagementGuard({ children }: { children: React.ReactNode }) {
  const { user } = useAuth();
  if (!user?.roles.includes('admin')) {
    return <Navigate to="/" replace />;
  }
  return <>{children}</>;
}
```
